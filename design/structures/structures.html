Structures

The facility registry the planner multiplies against — where industry happens changes materials, time, and cost, so every calculation is per-facility. One default per activity: the planner pre-selects it and the build plan can override per job.

wireframe This is the first of the three surface mockups (M3, M15, M12) — a single new page type proposed against the reference component set. The registry table, the add/edit form (shown in edit state with the system type-ahead open), the sync import card, and the multiplier reference card are all new; everything else is the standard chrome.

wireframe Registrations are per structure × activity (the TODO spec's form leads with Activity, and defaults are per activity — an engineering complex covers manufacturing, invention, and copying simultaneously, so it can appear in more than one group; the Police Weapons Facility does, above). Rigs and the default flag live on the registration. Supercapital assembly is a structure-level capability flag (the Hel/Ragnarok facility-class pin): supercapitals and titans build only in structures with it — the capability gates the final hull job, not the component builds, which any engineering complex hosts. No registered structure holds it today (corrected 2026-11-22: the corp's "5 times nearly AT winners" is a Keepstar market hub — no industry lines; it belongs to the market manager, not this registry), so Hel/Ragnarok plans surface the capability as an acquisition gap on the final hull job. Biochemical reactions (the Crash chain's pin) are still open: whether the reaction facilities above cover biochemical formulas or need a distinct facility class is unresolved — the reactions group may grow a biochemical capability distinction at implementation. Setting a new default in a group demotes the previous one (proposed behavior — the alternative, leaving an activity default-less until explicitly cleared, is more explicit but easier to leave in a half-configured state).

wireframe Security derives from the system — a proposal refining the TODO spec's hand-entered field: ESI carries security_status on every system, so the chosen system fills it; the manual control only exists for registrations without a system (where rig effectiveness still needs a security class). The supercapital checkbox appears only for engineering complexes (the capability is a structure service/rig choice, not a Sotiyo guarantee) and is validated, not trusted: confirmed 2026-11-22 that no Amamake (lowsec) facility can hold it, and the working assumption — supercapital production requires a player-owned structure in nullsec — is a pin needing confirmation from CCP structure docs at implementation; a supercap flag on a highsec/lowsec system fails validation rather than surfacing later as a broken plan. Copying is absent from the activity enum (manufacturing / invention / reactions per the spec): the M9 copy layer needs a facility default for copy jobs too — decide at M3 whether Copying joins the enum or rides the invention registration, since ECs host both.

wireframe This card is a proposal beyond the TODO spec (which notes only that universe_locations already stores seen structures): the sync's structure sightings become import suggestions instead of a second manual entry path. NPC stations don't appear here — the 40 synced station rows are complete SDE/ESI data, so registering one is a search-and-select in the form, not an import. Structures without industry lines (the Keepstar market hub) stay listed but unimportable — they route to the market manager instead, which is how the two registries divide the world: industry facilities here, markets there.
